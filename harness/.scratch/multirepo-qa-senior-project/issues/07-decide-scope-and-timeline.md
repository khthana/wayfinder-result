# 07 — ตัดสิน: ขอบเขตที่คนเดียวทำไหวใน 2 ภาคเรียน + milestones

Type: grilling
Status: resolved
Blocked by: 05, 06

## Question

นักศึกษาทำคนเดียว ~8 เดือน **ตัดอะไรออกและเหลืออะไรไว้**?

ต้องตัดสิน:
- ขอบเขตขั้นต่ำที่ยังเป็นโครงงานที่สมบูรณ์ (ถ้าทุกอย่างช้ากว่าแผน อะไรคือสิ่งที่ยังต้องส่งได้)
- ขอบเขตที่ตั้งใจไว้ และขอบเขตที่จะทำถ้ามีเวลาเหลือ
- milestone รายเดือน แบ่งตาม 2 ภาคเรียน (ภาคแรก: literature + baseline + benchmark, ภาคสอง: ระบบ + วัดผล + เขียนเล่ม — หรือแบ่งอย่างอื่นถ้าเหมาะกว่า)
- **จุดตัดสินใจ (go/no-go) ที่ชัดเจน** ระหว่างทาง เพื่อให้อาจารย์ดึงกลับทันถ้าหลงทาง
- ความเสี่ยงหลักสามข้อและแผนสำรองของแต่ละข้อ

## Answer

### ใช้ GPU server อย่างไรให้คุ้ม

- **GPU → embedding model โลคัล** (Qwen3-Embedding ตระกูล) และ **LLM-as-judge** — ปริมาณเรียกสูง ต้นทุนต่อครั้งต้องเป็นศูนย์
- **API frontier model → ตัว agent เท่านั้น** — เรียกน้อยครั้งกว่ามาก คุมงบได้
- **ห้ามใช้ local LLM เป็นตัว agent** — โมเดลเปิดยังอ่อนกับงาน agentic tool-calling จะทำให้ผลการทดลองวัดความอ่อนของโมเดล ไม่ได้วัดวิธีการ

### สิ่งที่ต้องห้ามมอบหมาย เพราะไม่มีพื้น IR

- เขียน static analyzer หรือสร้าง code graph database เอง
- เทรน embedding model เอง
- จูน chunking strategy — **ตั๋ว 01 ยืนยันว่าได้ผลน้อยมาก** (cAST +4.3 Recall@5; JetBrains พบ line-based เทียบเท่า syntax-aware) เสียเวลาเปล่า

**ใช้ tree-sitter แทน** — เรียนรู้ได้ใน ~2 สัปดาห์ และเพียงพอกับการดึงชื่อ symbol

### Timeline

**ภาคเรียนที่ 1**

| เดือน | งาน | ส่งมอบ |
|---|---|---|
| 1 | อ่านวรรณกรรม + ปูพื้น IR (BM25, recall@k, MRR, nDCG) | annotated bibliography + baseline ripgrep+LLM ที่รันได้ |
| 2 | เลือก corpus + **วัด collision rate** | **ผลเชิงประจักษ์ชิ้นแรก** |
| 3 | สร้างชุดประเมิน (~200 คำถาม, ~100 ตรวจมือ) | dataset v1 |
| 4 | รัน baseline ทั้งสามตัวบน dataset | สอบหัวข้อ + ตัวเลข baseline |

**ภาคเรียนที่ 2**

| เดือน | งาน | ส่งมอบ |
|---|---|---|
| 5 | ออกแบบ + สร้างชั้น disambiguation v1 | เครื่องมือที่รันได้ |
| 6 | วัดผล + ablation + วิเคราะห์สถิติ | ตารางผลหลัก |
| 7 | วิเคราะห์ failure + รัน corpus ชั้นสอง (org จริง) | ผลบนของจริง |
| 8 | เขียนเล่ม + เตรียมสอบ | เล่มสมบูรณ์ |

### จุด go/no-go — เขียนลง proposal ให้ชัด

- **สิ้นเดือน 2**: collision rate ต้องไม่ต่ำจนไร้นัยสำคัญ ถ้าต่ำ → เปลี่ยนไปทำ contribution แบบ benchmark ทันที **ยังเหลือเวลา 6 เดือน**
- **สิ้นเดือน 4**: baseline ต้อง**ตกจริง**บนคำถามที่ entity ชน ถ้า baseline ทำได้ดีอยู่แล้ว = ไม่มี headroom → เปลี่ยนไปทำ staleness study
- **สิ้นเดือน 6**: ถ้าวิธีที่เสนอไม่ชนะ baseline → **ไม่ต้องเปลี่ยนหัวข้อ** รายงานเป็น negative result พร้อมวิเคราะห์สาเหตุ

### ขอบเขตขั้นต่ำที่ยังจบได้ (ถ้าทุกอย่างช้ากว่าแผน)

**collision measurement study + evaluation set + baseline comparison** — แค่สามอย่างนี้ก็เป็นโครงงานที่สมบูรณ์แล้ว เพราะเป็นงานวัดผลที่ไม่มีใครทำ ส่วนชั้น disambiguation เป็นส่วนต่อยอด

### ความเสี่ยงหลักและแผนสำรอง

| ความเสี่ยง | แผนสำรอง |
|---|---|
| การชนของชื่อเกิดน้อยเกินไป | วัดตั้งแต่เดือน 2 เปลี่ยนเป็น benchmark contribution |
| baseline เก่งอยู่แล้ว ไม่มี headroom | วัดเดือน 4 เปลี่ยนเป็น staleness study |
| LLM-as-judge ไม่น่าเชื่อถือ (κ ต่ำ) | เช็ค κ ก่อนใช้ ถ้าต่ำเปลี่ยนไปใช้ retrieval metric เป็นหลัก |
| ไหลไปสร้าง agent เต็มระบบ | **ใช้ agent ที่มีอยู่เป็น harness เติมแค่ชั้น disambiguation** — ข้อนี้เสี่ยงที่สุดสำหรับนักศึกษาที่อยากสร้างของเจ๋ง อาจารย์ต้องคอยดึง |
