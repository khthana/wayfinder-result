# 08 — ตัดสิน: VoC interviews จำเป็นไหม และถ้าจำเป็นถามอะไร

Type: grilling
Status: resolved
Blocked by: 05

## Question

นักศึกษาระบุว่าต้องสัมภาษณ์เพื่อน 3-5 คน (full-stack/backend/DevOps) แต่ยังไม่ได้ทำ

ต้องตัดสิน:
- การสัมภาษณ์นี้ **เปลี่ยนการตัดสินใจอะไรได้จริงไหม** หรือเป็นแค่พิธีกรรมที่ทำให้ proposal ดูดี — ถ้าเปลี่ยนอะไรไม่ได้ ควรตัดทิ้งเพื่อประหยัดเวลา
- ถ้าทำ: คำถามที่จะถาม ควรมุ่งพิสูจน์ว่า pain point ข้าม repo มีอยู่จริงและเกิดบ่อยแค่ไหน ไม่ใช่ถามว่าอยากได้ฟีเจอร์อะไร
- นักศึกษาปีสี่ที่ยังไม่เคยทำงานจริง เป็นตัวแทนของผู้ใช้กลุ่มเป้าหมายได้แค่ไหน และข้อจำกัดนี้จะเขียนลงเล่มอย่างไร

## Answer

**ลดบทบาทลง แต่ไม่ตัดทิ้ง — ทำแบบจำกัดเวลาไว้ 1 สัปดาห์ในเดือนที่ 2**

**เหตุผลที่ลดบทบาท**: หลังปรับกรอบ ข้ออ้างหลักของโครงงาน**พิสูจน์ได้จากโค้ดโดยตรง** — collision rate วัดจาก repo จริงได้ ไม่ต้องถามใคร การสัมภาษณ์จึงไม่ใช่หลักฐานสนับสนุน contribution อีกต่อไป

**เหตุผลที่ยังไม่ตัดทิ้ง**: ภาควิชารับงานแบบ "ระบบใช้งานได้จริง" ด้วย การมี user grounding ช่วยบทที่ 1 และช่วยตอบกรรมการที่ถามว่า "ปัญหานี้มีจริงไหม"

**ถามอะไร** — ถามความถี่ของความเจ็บปวด ไม่ใช่ถามว่าอยากได้ฟีเจอร์อะไร:
- ครั้งล่าสุดที่หาโค้ดข้าม repo ไม่เจอคือเมื่อไหร่ ใช้เวลาเท่าไหร่
- เคยแก้ผิด service เพราะชื่อ class เหมือนกันไหม
- ตอนนี้ใช้วิธีอะไรหา (grep? ถามรุ่นพี่? ไล่อ่าน?)

**ข้อจำกัดที่ต้องเขียนลงเล่มตรงๆ**: นักศึกษาปีสี่ที่ยังไม่เคยทำงาน**ไม่ใช่ตัวแทน**ของ developer ที่ทำงานกับ polyrepo ระดับองค์กร — ใช้เป็น motivating evidence ได้ ใช้เป็นหลักฐานสนับสนุนผลไม่ได้ **การเขียนข้อจำกัดนี้เองแสดงวุฒิภาวะเชิงวิจัย และมักได้คะแนนจากกรรมการ**
