# ตัวเลือกชื่อหัวข้อโครงงาน

สถานะ: **ข้อเสนอ ยังไม่ได้เลือก** — เขียนไว้ 7 ส.ค. 69 ตามที่อาจารย์ขอ
ทุกแบบเปลี่ยนได้ ส่วนที่เป็นข้อจำกัดจริงอยู่ใน §"สามกับดัก" ท้ายไฟล์

---

## แบบ A — เน้นว่าเป็น "ผู้ช่วย" ไม่ใช่ "ผู้ตัดสิน" ⭐ ที่แนะนำ

**ไทย:** ระบบผู้ช่วยตรวจงานออกแบบประสบการณ์และส่วนต่อประสานผู้ใช้ด้วยเอเจนต์ปัญญาประดิษฐ์เชิงหลายรูปแบบ โดยมีอาจารย์เป็นผู้ยืนยันผลขั้นสุดท้าย

**อังกฤษ:** A Multimodal AI Agent for Assisting UX/UI Design Assessment with Instructor-in-the-Loop Confirmation

ตรงกับสิ่งที่ระบบเป็นจริงที่สุด และตัดคำถามอันตรายที่สุดของกรรมการทิ้งตั้งแต่หน้าปก — *"ให้ AI ตัดเกรดนักศึกษาเหรอ"* ชื่อตอบไปแล้วว่าไม่ใช่ ตรงกับ flow ที่ตัดสินไว้แล้วว่า **AI ตรวจ → อาจารย์ยืนยัน/แก้ → นักศึกษาเห็นคะแนน**

---

## แบบ B — เน้นเกณฑ์รูบริกกับตัวโมเดล

**ไทย:** การประเมินงานออกแบบส่วนต่อประสานผู้ใช้ตามเกณฑ์รูบริกด้วยแบบจำลองภาษาขนาดใหญ่เชิงหลายรูปแบบ

**อังกฤษ:** Rubric-Based Assessment of User Interface Design Using Multimodal Large Language Models

ชื่อที่ค้นเจอง่ายที่สุดใน Google Scholar เพราะใช้คีย์เวิร์ดที่วงการใช้จริง เหมาะถ้าจะเขียนบทความต่อ
ข้อเสีย: ไม่ได้บอกว่ามีอาจารย์อยู่ในลูป

---

## แบบ C — เน้นสถาปัตยกรรมสองชั้น (contribution ทางเทคนิคจริง ๆ)

**ไทย:** สถาปัตยกรรมการตรวจงานออกแบบ UX/UI แบบผสมระหว่างชั้นกฎที่ตรวจสอบได้กับชั้นแบบจำลองภาษาขนาดใหญ่

**อังกฤษ:** A Hybrid Rule-and-LLM Architecture for Grading UX/UI Design Assignments

เหมาะถ้ากรรมการเป็นสาย CS แล้วจะถามว่า "ของใหม่คืออะไร ไม่ใช่แค่เรียก API เหรอ" — ชื่อนี้ตอบก่อนถูกถาม ว่าการแยกสิ่งที่วัดได้ออกจากสิ่งที่ต้องตีความคือตัวงาน (ดูตัวอย่างที่รันได้จริงใน `sample-agent/`)

---

## แบบ D — เน้น outcome-based / สืบย้อนได้ (สาย TABEE)

**ไทย:** ระบบสนับสนุนการประเมินผลลัพธ์การเรียนรู้สำหรับงานออกแบบ UX/UI ที่ให้คะแนนพร้อมหลักฐานสืบย้อนได้

**อังกฤษ:** An Outcome-Based Assessment Support System for UX/UI Coursework with Traceable, Evidence-Linked Scoring

พูดภาษาเดียวกับฝ่ายประกันคุณภาพ เหมาะถ้าจะดันเรื่องนี้ต่อในระดับหลักสูตร
ข้อเสีย: ฟังดูเป็นงานการศึกษามากกว่างานวิศวกรรม

---

## แบบ E — แคบและชัด ระบุ Figma ตรง ๆ

**ไทย:** ระบบตรวจงานต้นแบบ Figma ในรายวิชาออกแบบส่วนต่อประสานผู้ใช้ด้วยเอเจนต์ปัญญาประดิษฐ์

**อังกฤษ:** An AI Agent for Grading Figma Prototypes in User Interface Design Courses

ตรงกับขอบเขตจริงที่สุด (ชิ้นงานที่ตรวจ = Figma + PDF เท่านั้น)
ข้อเสีย: ผูกชื่อไว้กับผลิตภัณฑ์ของบริษัทหนึ่ง ซึ่งบางภาควิชาไม่ให้ใส่ในชื่อปริญญานิพนธ์

---

## สามกับดักที่ควรเลี่ยง

**อย่าใช้คำว่า "อัตโนมัติ" / "Automated"**
ระบบนี้ไม่ได้ตัดสินเอง flow ที่ตกลงกันไว้คือ AI ตรวจ → อาจารย์ยืนยัน/แก้ → นักศึกษาเห็นคะแนน
ใส่คำนี้ไปคือสัญญาสิ่งที่ระบบไม่ได้ทำ แล้วจะโดนซักตอนสอบ

**อย่าใส่ RL ในชื่อ**
งาน RL อยู่ในภาค 2 และเป็นส่วนที่เสี่ยงที่สุด — ยังไม่รู้ว่ามีข้อมูลพอไหม (ยังไม่ได้นับจำนวนชิ้นงานเก่า ดู checklist ท้ายเอกสาร 04)
ถ้าใส่ในชื่อแล้วทำไม่ทัน จะแก้ชื่อตอนใกล้ส่งเล่มไม่ได้ ให้ RL อยู่ในบทที่ 5 ในฐานะงานต่อยอดจะปลอดภัยกว่ามาก

**เช็กกับภาควิชาว่ายอมให้ใช้ตัวย่อ "UX/UI" ในชื่อไทยไหม**
บางที่บังคับให้เขียนเต็มว่า "ประสบการณ์ผู้ใช้และส่วนต่อประสานผู้ใช้" (เขียนแบบเต็มไว้แล้วในแบบ A)

---

## ข้อเสนอสุดท้าย

ใช้ **แบบ A** สำหรับหน้าปกและเอกสารทางการ แล้วใช้ **แบบ C** เป็นชื่อรองในสไลด์บทที่ 3 ตอนอธิบายสถาปัตยกรรม
สองชื่อนี้เสริมกัน — A บอกว่าระบบทำอะไรเพื่อใคร C บอกว่ามันใหม่ตรงไหน

ชื่อเรียกสั้นในสไลด์และในโค้ด: **UX Grading Agent** / ภาษาไทย **ระบบช่วยตรวจงานออกแบบ**

**ยังต้องการจากอาจารย์:** ภาควิชาและสายของกรรมการสอบ เพื่อปรับสำนวนให้ตรงกับที่ภาคนั้นใช้
