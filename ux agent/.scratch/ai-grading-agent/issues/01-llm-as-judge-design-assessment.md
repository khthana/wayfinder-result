# 01 — LLM-as-judge สำหรับการประเมินงานออกแบบตาม rubric

Type: research
Status: resolved
Blocked by: —

## Question

สถานะปัจจุบันของการใช้ LLM ตรวจงานตาม rubric เป็นอย่างไร และมีแนวปฏิบัติอะไรที่พิสูจน์แล้วว่าทำให้คะแนนน่าเชื่อถือขึ้น?

ต้องการคำตอบที่ครอบคลุม

1. **งานวิจัยหลัก** ด้าน LLM-as-a-judge และ Automated Essay Scoring (AES) ที่ใช้ rubric — ผลลัพธ์ที่รายงานไว้ ระดับ agreement กับมนุษย์ที่ทำได้จริง (ตัวเลข QWK/Cohen's kappa ที่ถือว่า "ดี" ในวรรณกรรม)
2. **อคติที่รู้จักแล้วของ LLM judge** — position bias, verbosity bias, self-enhancement bias, ความลำเอียงไปทางคะแนนกลาง ๆ, ความไม่คงเส้นคงวาเมื่อรันซ้ำ — และวิธีลดผลกระทบแต่ละอย่าง
3. **เทคนิคที่เพิ่มความน่าเชื่อถือ** — chain-of-thought ก่อนให้คะแนน, การแตก rubric เป็น criterion แล้วตรวจทีละข้อแทนการให้คะแนนรวม, การใช้ reference answer, ensemble/self-consistency, การบังคับให้อ้างหลักฐานจากชิ้นงาน
4. **การประเมินงานที่เป็นภาพ/งานออกแบบโดยเฉพาะ** — มีงานวิจัยที่ใช้ vision model ตรวจ UI/UX artifact ไหม (เช่น การประเมิน heuristic ของ Nielsen ด้วย LLM, การตรวจ accessibility, การให้ feedback งานออกแบบ) ผลเป็นอย่างไร
5. **การออกแบบ prompt/agent สำหรับการตรวจ** — single-shot vs multi-agent (แยก agent ต่อ criterion), การให้ agent เรียกเครื่องมือดูชิ้นงานหลายมุม, การจัดการชิ้นงานที่ยาว/หลายหน้า
6. **ข้อจำกัดที่ยอมรับกันแล้ว** — อะไรที่ LLM ตรวจได้แม่น อะไรที่ยังตรวจไม่ได้ (เช่น ความคิดสร้างสรรค์ ความเหมาะสมกับบริบทผู้ใช้)

เน้นแหล่งปฐมภูมิ: arXiv, ACL/EMNLP/CHI/LAK proceedings, เอกสารทางการของผู้ให้บริการโมเดล หลีกเลี่ยงบล็อกการตลาด
