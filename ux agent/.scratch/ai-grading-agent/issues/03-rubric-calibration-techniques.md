# 03 — เทคนิคปรับ rubric/prompt ให้คะแนน AI ตรงกับอาจารย์ และวิธีวัดว่าตรงแค่ไหน

Type: research
Status: resolved
Blocked by: —

## Question

มีเทคนิคอะไรบ้างที่ทำให้ระบบ "เรียนรู้" จากคะแนนที่อาจารย์ให้ โดยไม่ต้องแตะน้ำหนักโมเดล และจะวัดความสำเร็จอย่างไรให้เป็นวิทยาศาสตร์?

ต้องการคำตอบที่ครอบคลุม

1. **มาตรวัดความสอดคล้อง** — Quadratic Weighted Kappa, Cohen's/Krippendorff's alpha, ICC, MAE/RMSE, exact & adjacent agreement — แต่ละตัวเหมาะกับข้อมูลแบบไหน, ค่าเท่าไรถือว่ายอมรับได้ในวรรณกรรมด้านการศึกษา, ต้องมีกี่ตัวอย่างจึงจะมีนัยสำคัญ (สำคัญมาก เพราะโครงงานนี้มีข้อมูลหลักสิบถึงหลักร้อย)
2. **Few-shot example selection** — การเลือกตัวอย่างงานที่อาจารย์ตรวจแล้วใส่เข้าไปใน prompt: เลือกอย่างไร (ครอบคลุมทุกระดับคะแนน? ใกล้เคียงกับงานที่กำลังตรวจ? anchor papers แบบที่ใช้ในการตรวจข้อสอบอัตนัย), ใส่กี่ตัวอย่างจึงพอ, ผลที่รายงานไว้
3. **การปรับข้อความ rubric อัตโนมัติ** — งานด้าน automatic prompt optimization (เช่น APE, OPRO, DSPy, TextGrad, "prompt as gradient") ใช้กับการปรับถ้อยคำเกณฑ์ให้ AI ตีความตรงกับอาจารย์ได้ไหม ต้องมีข้อมูลเท่าไร
4. **การปรับเชิงตัวเลข** — score calibration / isotonic regression / bias correction ต่อ criterion (ถ้า AI ให้คะแนนสูงกว่าอาจารย์ 0.7 จุดเสมอในเกณฑ์หนึ่ง จะแก้ที่ prompt หรือแก้ที่ post-processing)
5. **Active learning / sampling** — ควรสุ่มงานให้อาจารย์ตรวจซ้ำอย่างไรให้ได้ข้อมูลที่มีค่าที่สุดต่อการ calibrate (สุ่มล้วน? เลือกงานที่ AI ไม่มั่นใจ? เลือกงานที่คะแนนอยู่ใกล้เส้นแบ่งเกรด?)
6. **การจัดการเมื่อ rubric เปลี่ยน** — วรรณกรรมพูดถึงการรักษาความเทียบเคียงของคะแนนข้ามเวอร์ชันเกณฑ์อย่างไร
7. **Inter-rater reliability ของมนุษย์เอง** — อาจารย์คนเดียวกันตรวจงานเดิมสองครั้งยังได้คะแนนต่างกัน ตัวเลขนี้เป็นเพดานบนของ AI — วรรณกรรมรายงานไว้เท่าไรสำหรับงานออกแบบ/งานอัตนัย

เน้นแหล่งปฐมภูมิ: arXiv, ACL/EMNLP, Learning Analytics (LAK), Educational Measurement journals

## Answer

ผลการค้นอยู่ที่ [`research/03-rubric-calibration.md`](../research/03-rubric-calibration.md) — 414 บรรทัด 8 หัวข้อ

หัวข้อ: มาตรวัดความสอดคล้อง (QWK พร้อมสูตร, alpha, ICC, MAE) · ⭐ **หัวข้อ 2 ตอบคำถามที่แพงที่สุดของโครงงาน: "มี N ตัวอย่าง วัดอะไรได้ ปรับอะไรได้"** · inter-rater reliability ของมนุษย์ในฐานะเพดานบนของ AI · few-shot/anchor selection · automatic prompt/rubric optimization · **score post-calibration — แก้ที่ตัวเลขไม่ใช่ที่ prompt** · active learning เลือกว่าให้อาจารย์ตรวจงานชิ้นไหน · การเปรียบเทียบคะแนนเมื่อ rubric เปลี่ยนเวอร์ชัน

ข้อสรุปที่บังคับการออกแบบ data model ทันที (ส่งต่อ ticket 10 และ 12):

1. **rubric ต้องเป็น immutable versioned object** — ทุกคะแนนผูกกับ `rubric_version_id` ห้าม edit in place เด็ดขาด
2. anchor set ผูกกับเวอร์ชันด้วย — anchor ของ v1 ใช้กับ v2 ไม่ได้โดยอัตโนมัติ
3. เก็บ **bridge set ~15–25 ชิ้นที่ตรวจด้วยทั้งสองเวอร์ชัน** เพื่อประมาณ shift และ rescale ตอนเปลี่ยน rubric
4. รีเซ็ตค่า calibration เมื่อ rubric เปลี่ยนอย่างมีความหมาย ไม่ carry over
5. **แยก "rubric ที่แสดงต่อนักศึกษา" ออกจาก "rubric prompt ที่ AI ใช้"** — ผูกเวอร์ชันเดียวกันได้แต่ปรับถ้อยคำอิสระต่อกัน เพราะ rubric ที่ดีสำหรับมนุษย์ไม่จำเป็นต้องดีสำหรับ LLM
