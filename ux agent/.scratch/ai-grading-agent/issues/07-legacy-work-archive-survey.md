## Answer (7 ส.ค. 69 — อาจารย์ตอบจากความจำ ยังไม่ได้เปิดโฟลเดอร์จริง)

> "งานเก่ามีครับ แต่ผลการตอบยังเชื่อถือไม่ได้ เพราะเป็นการตรวจแบบ มี/ไม่มี ไม่มีการตรวจเชิงคุณภาพ
> 1) link figma ไม่แน่ใจ อาจจะมีครับ เพราะส่วนใหญ่น่าจะยังไม่ได้ลบ 2) แยกครับ แต่เชื่อถือไม่ได้อย่างที่บอก
> 3) มีงานครบ 4) ไม่ต้องผ่าน"

| ข้อ | คำตอบ | ผล |
|---|---|---|
| มีคลังงานไหม | **มี** | มี corpus ของงานจริงให้ใช้ |
| ครบทั้งช่วงคะแนนไหม | **ครบ** | ไม่ต้องกังวลเรื่องชุดข้อมูลเอียงไปทางงานดี |
| คะแนนเดิมแยกตามเกณฑ์ย่อยไหม | **แยก แต่เชื่อถือไม่ได้** | ดู §1 — เป็นข้อที่เปลี่ยนแผนมากที่สุด |
| ลิงก์ Figma ยังเปิดได้ไหม | **ไม่แน่ใจ ส่วนใหญ่น่าจะยังไม่ถูกลบ** | **ตรวจแล้ว 5 ชิ้น ยังอยู่ครบ 5** ดู §5 |
| ต้องผ่านคณะกรรมการจริยธรรม | **ไม่ต้อง** | ความเสี่ยงเรื่องตารางเวลาที่ใหญ่ที่สุดของตั๋วนี้หายไป |

### §1 คะแนนเดิมใช้เป็น ground truth ไม่ได้ — และนี่คือข้อค้นพบหลักของตั๋วนี้

การตรวจเดิมเป็นแบบ **มี/ไม่มี** (ส่งครบไหม มีองค์ประกอบที่สั่งไหม) ไม่ใช่การตัดสินเชิงคุณภาพ
ต่อให้คะแนนแยกตามเกณฑ์ย่อยไว้แล้ว ตัวเลขนั้นก็ตอบคำถามคนละข้อกับที่ระบบใหม่จะตอบ

**บทบาทของคลังงานจึงพลิก:**

| เดิมคาดว่า | ที่จริงคือ |
|---|---|
| ข้อมูลที่มี label มาแล้ว ใช้วัดผลได้เลย | **corpus ของงานจริงที่ยังไม่มี label** + งานที่อาจารย์ต้องตรวจใหม่ |

สิ่งที่ได้ฟรียังมีค่ามาก — **การเก็บงานจริงที่ครอบคลุมทั้งช่วงคุณภาพคือส่วนที่ยากและช้าที่สุด** และส่วนนั้นทำเสร็จแล้ว สิ่งที่ยังต้องลงแรงคือการให้คะแนน ซึ่งควบคุมเวลาได้

คะแนนเดิมยังใช้ได้อยู่หนึ่งอย่าง: **ใช้เป็นตัวช่วยสุ่มตัวอย่างให้กระจาย** (stratified sampling) — บอกคร่าว ๆ ได้ว่าชิ้นไหนส่งครบ ชิ้นไหนส่งไม่ครบ จะได้ไม่หยิบมาแต่งานประเภทเดียว **แต่ห้ามใช้เป็นเฉลย** และห้ามให้อาจารย์เห็นคะแนนเดิมตอนตรวจใหม่

### §2 ผลพลอยได้สองข้อที่ได้มาฟรีจากข้อเท็จจริงนี้

**(ก) การตรวจใหม่คือ blind grading โดยธรรมชาติ**
ticket 04 ระบุว่าตัวเลขผลการทดลองทั้งโครงงานจะมีความหมายก็ต่อเมื่ออาจารย์ตรวจโดยไม่เห็นคะแนน AI ก่อน — ซึ่งเป็นภาระที่ต้องแบกตลอดสองเทอม
แต่การตรวจงานเก่าที่ยังไม่เคยมี AI แตะเลย **เป็น blind โดยอัตโนมัติ** ไม่ต้องออกแบบโหมดพิเศษ ไม่ต้องอาศัยวินัย ทำให้ gold set ชุดแรกสะอาดที่สุดเท่าที่จะเป็นไปได้

**(ข) โครงงานได้ปัญหาวิจัยที่คมขึ้นมาฟรี ๆ**
"ระบบเดิมตรวจได้แค่ มี/ไม่มี เพราะการตรวจเชิงคุณภาพด้วยมือแพงเกินไปในปริมาณนั้น" — นี่คือ **ข้อความปัญหาของโครงงานที่มีหลักฐานจริงรองรับ** ไม่ใช่คำกล่าวอ้างลอย ๆ ในบทที่ 1 และสอดคล้องกับข้อสังเกตเดิมว่า *รูปแบบของงานในระบบเดิมคือผลผลิตของข้อจำกัดว่าอะไรทำด้วยมือได้เร็ว*

### §3 ตัวเลขที่ตั๋วนี้ต้องส่งมอบ: อาจารย์ต้องตรวจงานเก่าใหม่กี่ชิ้น

ข้อเสนอ — **แบ่งชุดก่อนตรวจ ไม่ใช่หลังตรวจ**:

| ชุด | จำนวน | ใช้ทำอะไร |
|---|---|---|
| **ชุดพัฒนา (dev)** | ~40 ชิ้น | นักศึกษาดูได้เต็มที่ ใช้ปรับ prompt / rubric / few-shot |
| **ชุดวัดผล (test)** | ~60 ชิ้น | **ล็อกไว้ ห้ามเปิดดูระหว่างพัฒนา** ใช้ครั้งเดียวตอนรายงานผลในเล่ม |

รวม ~100 ชิ้น ที่ 10–15 นาทีต่อชิ้น ≈ **20–25 ชั่วโมงของอาจารย์** ถ้ามากเกินไป ลดเหลือ 30/50 = 80 ชิ้นได้ แต่ต่ำกว่านี้ช่วงความเชื่อมั่นจะกว้างจนสรุปอะไรไม่ได้

**ต้องเป็นอาจารย์ตรวจเอง ให้ TA ตรวจแทนไม่ได้** เพราะสิ่งที่โครงงานวัดคือ "AI ให้คะแนนใกล้อาจารย์แค่ไหน" ถ้าเฉลยมาจากคนอื่น ตัวเลขก็วัดคนละอย่าง

รายละเอียดระเบียบวิธี (เลือกชิ้นยังไง ตรวจซ้ำเพื่อวัดความคงเส้นคงวาของตัวอาจารย์เองไหม) เป็นเนื้อของ **ticket 15**

### §4 ข้อที่ยังค้าง — ตรวจได้ใน 15 นาที

  *ข้อควรระวังแม้เปิดได้:* ไฟล์ Figma เก่าอาจถูกนักศึกษาแก้ต่อหลังส่ง สิ่งที่เห็นวันนี้จึงไม่จำเป็นต้องเท่ากับสิ่งที่ส่งตอนนั้น — สำหรับ gold set ยอมรับได้ (ตรวจตามที่เห็น) แต่ต้องบันทึกวันที่ดึงภาพไว้ และควรแช่แข็งเป็นภาพทันทีที่ดึง

### สิ่งที่การตรวจนี้ยังไม่ได้พิสูจน์

- **ยังไม่ได้เปิดจริงในเบราว์เซอร์ที่ล็อกเอาต์** — ส่วนขยาย Chrome ไม่ได้เชื่อมต่อในรอบนี้ ที่ได้มาคือ metadata + ภาพย่อ ซึ่งเป็นหลักฐานแรงแต่ไม่ใช่การเห็นทุกหน้าจอด้วยตา · ถ้าจะให้ปิดสนิท เปิดหน้าต่างไม่ระบุตัวตนแล้ววางลิงก์ทีละอัน ใช้เวลาไม่ถึง 5 นาที
- **ยังไม่ได้พิสูจน์ว่า Figma REST API อ่านได้** — ยิง `GET /v1/files/<key>` โดยไม่มี token ได้ `403 Invalid token` **ทั้งกับ key จริงและ key มั่ว** แปลว่า Figma ปฏิเสธที่ชั้น token ก่อนจะดูด้วยซ้ำว่า key มีอยู่ไหม → **การทดสอบนี้แยกไฟล์ที่เปิดได้ออกจากไฟล์ที่หายไปไม่ได้เลย** ต้องรอมี personal access token จริงก่อน (เป็นงานของ spike ใน ticket 17 อยู่แล้ว)
- 5 ชิ้นนี้**ไม่ได้สุ่ม** อาจารย์เลือกมาเอง ซึ่งเป็นชุดที่หาลิงก์เจอง่ายที่สุด → อัตราการรอด 5/5 เป็น **ขอบบน** ไม่ใช่ค่าประมาณของทั้งคลัง
- ข้อควรระวังเดิมยังอยู่: **ไฟล์อาจถูกแก้ต่อหลังส่ง** สิ่งที่เห็นวันนี้ไม่จำเป็นต้องเท่ากับสิ่งที่ส่งตอนนั้น → ต้องบันทึกวันที่ดึงและแช่แข็งเป็นภาพทันที

ชื่อโฟลเดอร์ที่ติดมากับ metadata (`Tea+`, `Team project`) และชื่อไฟล์ (`Untitled`, `Final`) เป็น**ตัวอย่างจริงของสองอย่างที่เอกสาร 01 ตัดสินไว้แล้ว**:

1. **ชื่อไฟล์เชื่อถือไม่ได้เลยในการระบุว่าเป็นงานของใคร/ชิ้นไหน** — `Untitled` กับ `Final` บอกอะไรไม่ได้ → ยืนยันว่าการผูกงานเข้ากับกลุ่มต้องมาจากการ enroll + การส่งงานในระบบ ไม่ใช่จากการอ่านชื่อไฟล์
2. **ชื่อโฟลเดอร์คือ metadata ที่ตามไฟล์มาโดยที่คนส่งไม่รู้ตัว** → เข้ากับกฎถอดตัวตนใน ticket 18 พอดี: `folder_name` เป็นหนึ่งในช่องที่ต้องถอดก่อนเข้าชั้น LLM และเป็นเหตุผลว่าทำไมการถอดต้องทำที่**ตัวสร้าง prompt** ไม่ใช่ที่หน้าจออัปโหลด

## §6 ปิดตั๋ว (7 ส.ค. 69) — ทำไมปิดได้ทั้งที่ยังไม่รู้จำนวนชิ้นงาน

ตั๋วนี้เปิดค้างอยู่เพราะการทำบัญชี ไม่ใช่เพราะมีอะไรตัดสินไม่ได้ · เกณฑ์ปิดตั๋วของแผนที่นี้คือ **"ทุกอย่างที่ต้องตัดสินใจถูกตัดสินแล้ว"** ไม่ใช่ "ข้อเท็จจริงทุกข้อถูกยืนยันแล้ว"

**สามข้อที่ตั๋วนี้ต้องตัดสิน ตัดสินครบแล้ว:**

| ต้องตัดสิน | ตัดสินแล้วว่า |
|---|---|
| คะแนนเดิมใช้เป็นเฉลยได้ไหม | **ไม่ได้** (§1) — เป็นข้อค้นพบหลักและพลิกบทบาทของคลังงานทั้งก้อน |
| ต้องตรวจใหม่กี่ชิ้น แบ่งยังไง | **~100 ชิ้น dev 40 / test 60 · ลดได้ถึง 80 (30/50) · ต่ำกว่านั้นสรุปไม่ได้** (§3) |
| ลิงก์ Figma เน่าไหม | **ไม่เน่า 5 จาก 5** (§5) |

**ส่วนตัวเลขจำนวนชิ้นงานไม่ใช่สิ่งที่ต้องตัดสิน แต่เป็นสิ่งที่ต้องนับ** และมันไม่ได้เปลี่ยนแผนหลักอีกแล้วตั้งแต่ ticket 23 ตัดสินว่า**วิชาเปิดสอนทุกภาค → gold set สร้างจากงานสดของภาค 1/2569 ได้** คลังงานเก่าจึงเลื่อนจาก "ฐานราก" ลงมาเป็น "ของเสริมความหลากหลาย + แผนสำรอง"

สิ่งที่ตัวเลขนี้ยังบอกได้จริงและมีค่า คือ **แผนสำรองที่เขียนไว้ในเอกสาร 04 มีอยู่จริงหรือเป็นแค่ชื่อ** — ด่านตัดสินใจ "ภาค 1 เป็นภาคเก็บข้อมูลได้ไหม" มีทางถอยเขียนว่า *ถอยไปเก็บข้อมูลจากงานเก่า (+20–25 ชม.)* ซึ่งจะจริงก็ต่อเมื่อคลังมีของถึง ~80 ชิ้น **ถ้ามี 40 ชิ้น ทางถอยนั้นไม่มีอยู่ และต้องรู้ก่อนถึงด่าน ไม่ใช่ตอนถึง**

→ **ย้ายไปเป็นรายการใน checklist ก่อนเริ่มโค้ดของเอกสาร 04** ในฐานะการยืนยันความเสี่ยง ไม่ใช่ตั๋วที่รอคำตอบ · การนับคร่าว ๆ พอ ไม่ต้องเปิดทุกชิ้น

**ข้อที่ยังไม่ได้ยืนยันและยอมรับว่ายังไม่ได้ยืนยัน:** ยังไม่ได้เปิดลิงก์ทั้ง 5 ด้วยตาในเบราว์เซอร์ที่ล็อกเอาต์ (ดูข้อจำกัดใน §5) — ถ้าอยากปิดจุดนี้ให้สนิท ใช้เวลาไม่ถึง 5 นาที แต่ไม่มีการตัดสินใจไหนรออยู่
