# 08 — Domain model และศัพท์กลางของระบบ

Type: grilling
Status: resolved
Blocked by: —

## Question

ระบบนี้พูดถึงสิ่งใดบ้าง แต่ละสิ่งหมายถึงอะไรแน่ ๆ และสัมพันธ์กันอย่างไร?

นี่คือ ticket รากของแผนที่ — เกือบทุก ticket ที่เหลือใช้คำที่ตัดสินที่นี่ ถ้าคำยังคลุมเครือ ทุกอย่างที่ต่อยอดจะคลุมเครือตาม ผลลัพธ์คือไฟล์ `CONTEXT.md` ที่รากของ effort (ใช้ `/domain-modeling`)

## คำที่ต้องนิยามให้คม

**โครงเรื่องรายวิชา**
- รายวิชา (Course) vs การเปิดสอนหนึ่งครั้ง (Course Offering / Section) — ถ้า "UX/UI Design" เปิดทั้ง 1/2569 และ 2/2569 นั่นคือหนึ่งสิ่งหรือสองสิ่ง; CLO และ rubric ผูกกับตัวไหน; ถ้าเทอมหน้าอยากคัดลอกของเดิมมาใช้ ต้องคัดลอกอะไรบ้าง
- ภาคการศึกษา (Term) — "1/2569" เป็นข้อมูลชนิดใด มีวันเริ่ม/สิ้นสุดไหม
- การลงทะเบียน (Enrollment) — ความสัมพันธ์ระหว่างนักศึกษากับการเปิดสอน; นศ. คนเดิมลงเรียนซ้ำจะเกิดอะไร
- ตารางเรียนรายสัปดาห์ (Week / Session) — ข้อ 4 บอกว่า "ไม่จำเป็นต้องมีทุกสัปดาห์" หมายถึงไม่มีการส่งงานทุกสัปดาห์ หรือไม่มีคาบเรียนทุกสัปดาห์ด้วย; สัปดาห์เป็นสิ่งที่มีตัวตนในระบบ หรือเป็นแค่วันที่บนงานชิ้นหนึ่ง

**งานและการส่ง**
- ชิ้นงาน/งานที่มอบหมาย (Assignment) vs การส่ง (Submission) vs ไฟล์ที่ส่ง (Artifact) — แยกกันชัดไหม; ส่งซ้ำ/ส่งแก้ทับของเดิมหรือเก็บเป็นเวอร์ชัน; ส่งช้าเป็นสถานะหรือเป็นการหักคะแนน
- กลุ่ม (Group) — ข้อ 6 บอกว่ากลุ่มเปลี่ยนได้ทุกครั้งที่ส่ง แปลว่ากลุ่มเป็นของ Assignment ไม่ใช่ของรายวิชา ยืนยันคำนี้ให้ตรงกันก่อน (รายละเอียดอยู่ที่ ticket 11)

**เกณฑ์และคะแนน**
- Rubric / เกณฑ์ย่อย (Criterion) / ระดับคุณภาพ (Level หรือ Performance Descriptor) / น้ำหนัก (Weight) — ตั้งชื่อไทยว่าอะไร ใช้คำไหนบนหน้าจอ
- คะแนน (Score) — ของใคร ของอะไร; คะแนนดิบ vs คะแนนที่ถ่วงน้ำหนัก vs คะแนนสุดท้าย
- การตรวจหนึ่งครั้ง (Assessment / Grading Run / Evaluation) — คำที่ใช้เรียก "เหตุการณ์ที่มีคนหรือ AI ให้คะแนนชิ้นงานหนึ่งด้วย rubric หนึ่ง"; ถ้าตรวจสองรอบ (AI แล้วอาจารย์) นับเป็นกี่เหตุการณ์ (รายละเอียดอยู่ที่ ticket 12)

**ผลลัพธ์การเรียนรู้**
- CLO — ผูกกับรายวิชาหรือกับการเปิดสอน; แก้ CLO กลางเทอมแล้วคะแนนเก่าเป็นอย่างไร
- CLO attainment — ของนักศึกษาคนหนึ่ง หรือของทั้งชั้น หรือทั้งสองระดับ

**คน**
- ผู้ใช้ (User) กับบทบาท (Role) — อาจารย์ / นักศึกษา / ผู้ช่วยสอน / ผู้ดูแลระบบ; คนหนึ่งมีหลายบทบาทข้ามรายวิชาได้ไหม (รายละเอียดอยู่ที่ ticket 18)

## สิ่งที่ต้องได้เมื่อจบ ticket

- `CONTEXT.md` ที่มีคำศัพท์พร้อมนิยาม เขียนแบบปราศจากรายละเอียดการ implement
- แผนภาพความสัมพันธ์ของ entity หลัก (ข้อความหรือ mermaid)
- รายการคำที่จงใจ **ไม่** ใช้ พร้อมเหตุผล (เช่น ถ้าเลิกใช้คำว่า "วิชา" ลอย ๆ เพราะกำกวมระหว่าง Course กับ Offering)

## Answer

ผลลัพธ์เต็มอยู่ที่ [`CONTEXT.md`](../CONTEXT.md) ที่รากของ effort — อภิธานศัพท์ แผนภาพความสัมพันธ์ และรายการคำต้องห้าม

ห้าประเด็นที่ตัดสินร่วมกับอาจารย์:

1. **แยกรายวิชา (Course) ออกจากการเปิดสอน (Course Offering)** — CLO, Rubric, สัปดาห์, ชิ้นงาน, รายชื่อ และคะแนน ผูกกับการเปิดสอนทั้งหมด ทำให้แต่ละเทอมปิดตัวเองสมบูรณ์ และคัดลอกข้ามเทอมได้
2. **สัปดาห์เป็น entity จริงของการเปิดสอน** — สร้างสัปดาห์ 1–16 ตอนเปิดเทอม ชิ้นงานผูกกับสัปดาห์ได้แต่ไม่บังคับ ตอบโจทย์ข้อ 4 ที่ว่า "ไม่จำเป็นต้องมีทุกสัปดาห์"
3. **การส่งซ้ำเก็บทุกเวอร์ชัน** — ส่งใหม่ = ระเบียนใหม่ ไม่ทับของเดิม และคะแนนชี้ไปที่เวอร์ชันที่ถูกตรวจจริง จำเป็นเป็นพิเศษกับ Figma เพราะไฟล์ถูกแก้ต่อได้โดยลิงก์ไม่เปลี่ยน
4. **การตรวจ (Assessment) = หนึ่งก้อนต่อผู้ตรวจหนึ่งราย** — AI ตรวจเป็นก้อนหนึ่ง อาจารย์ตรวจซ้ำเป็นอีกก้อนหนึ่ง ไม่เขียนทับกัน ก้อนของอาจารย์ถูกทำเครื่องหมายเป็นคำตัดสิน นี่คือประเด็นสำคัญที่สุดของ ticket เพราะส่วนต่างระหว่างสองก้อนคือสัญญาณเรียนรู้ทั้งหมดที่โจทย์ข้อ 8 และ 13 ต้องใช้ และยังเปิดทางให้ double-marking กับการเทียบหลายโมเดลโดยไม่ต้องแก้โครงสร้างทีหลัง
5. **คำศัพท์บนหน้าจอใช้ไทยเป็นหลัก ทับศัพท์เฉพาะ Rubric และ CLO** — เพราะเป็นคำที่วงการศึกษาใช้อยู่แล้ว การแปลจะทำให้สื่อสารกับอาจารย์ท่านอื่นยากขึ้น

ข้อกำหนดที่งอกออกมาและต้องส่งต่อ:

- ticket 17 — ตอนกดส่งต้อง **snapshot** ภาพและข้อมูล Figma ทันที เก็บลิงก์อย่างเดียวไม่พอ
- ticket 12 — คะแนนรายหัวข้อแขวนใต้ Assessment ไม่ใช่ใต้ Submission
- ticket 13 — การเชื่อม CLO อยู่ที่ระดับหัวข้อประเมิน (Criterion) ไม่ใช่ระดับชิ้นงาน
- ticket 18 — บทบาทผูกกับการเปิดสอน ไม่ใช่กับบัญชีผู้ใช้
- ยังไม่ตัดสิน: นโยบายงานส่งช้า (สถานะ vs การหักคะแนน) — ย้ายไปอยู่ที่ Not yet specified ของแผนที่
