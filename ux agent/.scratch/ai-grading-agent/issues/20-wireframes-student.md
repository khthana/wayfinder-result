## Question

หน้าจอฝั่งนักศึกษาควรมีอะไรบ้าง ให้ส่งงานถูกต้องตั้งแต่ครั้งแรกและเข้าใจคะแนนที่ได้?

ครอบคลุมโจทย์ข้อ 5 (หน้าส่งงาน), 6 (การจัดกลุ่ม), 12 (ดูคะแนนตนเอง)

## หน้าจอที่ต้องออกแบบ

1. **หน้าแรกของนักศึกษา** — รายวิชาที่ลงทะเบียนในเทอมปัจจุบัน; งานที่ยังไม่ส่งและใกล้ครบกำหนด เห็นได้ทันทีโดยไม่ต้องคลิกเข้าไปหา
2. **หน้ารายวิชา** — ตารางรายสัปดาห์ในมุมมองของนักศึกษา: สัปดาห์ไหนเรียนอะไร สัปดาห์ไหนต้องส่งอะไร ส่งแล้วหรือยัง ได้คะแนนเท่าไร
3. **หน้าส่งงาน** — หน้าจอที่ต้องออกแบบอย่างระวังที่สุดฝั่งนักศึกษา
   - แสดงโจทย์และกำหนดส่งชัดเจน
   - **แสดง rubric ที่จะใช้ตรวจให้นักศึกษาเห็นก่อนส่ง** — ต้องตัดสินว่าเปิดให้เห็นไหม (คำแนะนำ: เห็น เพราะเป็นหลักการพื้นฐานของ rubric ที่ดี และช่วยให้ นศ. รู้ว่าจะถูกวัดด้วยอะไร)
   - ช่องกรอกลิงก์ Figma พร้อมการตรวจสอบทันทีว่าลิงก์ถูกต้องและระบบเข้าถึงได้จริง — ถ้าเข้าไม่ได้ต้องบอกวิธีแก้เป็นขั้นตอน (เชื่อมกับ ticket 02) ไม่ใช่แค่ขึ้นว่า "เกิดข้อผิดพลาด"
   - ช่องอัปโหลดไฟล์ พร้อมข้อจำกัดชนิดและขนาดไฟล์ที่บอกไว้ล่วงหน้า
   - สถานะการส่ง: ส่งแล้วเมื่อไร ส่งช้าไหม แก้ไขได้ถึงเมื่อไร ส่งซ้ำได้กี่ครั้ง
4. **หน้าจัดกลุ่ม** — สร้างกลุ่มสำหรับงานชิ้นนี้ เชิญเพื่อน ตอบรับคำเชิญ ออกจากกลุ่ม; แสดงชัดว่ากลุ่มนี้ใช้กับงานชิ้นนี้เท่านั้น ไม่ใช่กลุ่มถาวรของวิชา (จุดที่ผู้ใช้เข้าใจผิดได้ง่ายที่สุดในระบบนี้)
5. **หน้าดูคะแนน** — คะแนนรายชิ้นงานและคะแนนสะสมของรายวิชา; เมื่อคลิกเข้าไปดูงานหนึ่งชิ้น เห็นคะแนนแยกตาม criterion พร้อมคำอธิบาย; **ต้องตัดสินจาก ticket 12 ว่านักศึกษาเห็นเหตุผลของ AI ไหม เห็นว่าอาจารย์แก้คะแนนไหม** และเห็น CLO attainment ของตัวเองไหม
6. **ช่องทางทักท้วง** — ถ้านักศึกษาไม่เห็นด้วยกับคะแนน ทำอะไรได้ (มีปุ่มขอทบทวนในระบบ หรือให้ไปคุยกับอาจารย์นอกระบบ) — ตัดสินว่าจะมีใน MVP ไหม

## §การส่งใหม่แบบมีราคา — แก้การตัดสินข้อ 1 (7 ส.ค. 69 รอบสอง)

> **อาจารย์:** "ข้อ 1 เรื่องส่งช้าแล้วอยากส่งอีก ผมยอมได้นะ แต่ต้องมีลงโทษ เช่น เอาคะแนนมาแลก"

ยกเลิกกติกาเดิมที่ว่า "ส่งซ้ำได้จนถึงกำหนดส่งเท่านั้น" — ส่งใหม่ได้เสมอ แต่มีราคา

### กลไกที่เลือก: ไม่ประดิษฐ์อะไรใหม่

**ค่าปรับคิดจากเวลาของครั้งที่ถูกใช้ตรวจ ไม่ใช่ครั้งแรกที่ส่ง**

กติกาหักวันละ 10% ของคะแนนเต็มมีอยู่แล้วใน ticket 25 การส่งใหม่ช้าลงหนึ่งวันจึงเท่ากับจ่ายเพิ่ม 10% โดยอัตโนมัติ **ไม่ต้องสร้างสกุลเงินใหม่ ไม่ต้องจำกัดจำนวนครั้ง ไม่ต้องมีตารางค่าปรับแยก**

ทางเลือกที่พิจารณาแล้วไม่เอา:

| ทางเลือก | ทำไมไม่เอา |
|---|---|
| หักคะแนนคงที่ต่อการส่งใหม่หนึ่งครั้ง | เป็นกฎเพิ่มที่ต้องอธิบาย ต้องตั้งตัวเลข และไม่สัมพันธ์กับความเสียหายจริง (คนส่งใหม่เร็วกับช้าจ่ายเท่ากัน) |
| จำกัดจำนวนครั้งที่ส่งใหม่ได้ | สร้างพฤติกรรมที่ไม่ต้องการ — นักศึกษาจะเก็บโควตาไว้แทนที่จะแก้งานเมื่อเห็นข้อผิดพลาด |
| ให้ส่งใหม่ฟรีแต่ใช้คะแนนสูงสุดของทุกครั้ง | ไม่มีราคาเลย และเพิ่มงานตรวจเป็นทวีคูณ |

**ผลพลอยได้ที่ตอบคำถามที่ยากที่สุดได้ในตัว** — คนที่ส่งตรงเวลาแล้วอยากแก้ต้องจ่ายอะไร? คำตอบคือเขาแลก **สถานะ "ตรงเวลา" ของตัวเอง** ไป ซึ่งเป็นราคาที่ยุติธรรมกับคนที่ส่งตรงเวลาแล้วไม่แก้ และไม่ต้องเขียนกฎเพิ่มแม้แต่บรรทัดเดียว

### ประตูที่สอง — สิ่งที่ค่าปรับปกป้องไม่ได้

**ค่าปรับปกป้องความยุติธรรมระหว่างนักศึกษา แต่ไม่ปกป้องเวลาของอาจารย์**

ถ้าส่งใหม่ได้เรื่อย ๆ หลังอาจารย์ตรวจไปแล้ว เท่ากับนักศึกษาบังคับให้ตรวจซ้ำได้ไม่จำกัดโดยจ่ายด้วยคะแนนของตัวเอง — ซึ่งไม่ใช่ทรัพยากรที่ขาดแคลนในโครงการนี้ เวลาของอาจารย์ต่างหากที่ขาดแคลน (เป็นเหตุผลทั้งหมดที่โครงงานนี้มีอยู่)

> **ปิดรับการส่งใหม่เมื่ออาจารย์กด "สั่งตรวจทั้งชุด"** — หลังจากนั้นเป็นการขอเป็นรายกรณี ไม่ใช่สิทธิ์

เลือกจุดตัดนี้เพราะเป็นเหตุการณ์ที่มีอยู่แล้วในผังลำดับของ ticket 17 D7 ไม่ต้องเพิ่มสถานะใหม่ในระบบ

### ข้อห้าม — การคลิกครั้งเดียวต้องทำลายคะแนนที่มีอยู่ไม่ได้

กติกา "เกิน 3 วันได้ 0 และระบบไม่ตรวจให้" ปลอดภัยตราบใดที่ยังไม่เคยส่ง แต่กลายเป็นกับดักทันทีเมื่อส่งใหม่ได้ — คนที่ส่งตรงเวลาไว้แล้วกดส่งใหม่ในวันที่ 4 จะเสียคะแนนทั้งหมดจากการคลิกครั้งเดียว **ระบบต้องปฏิเสธ ไม่ใช่เตือนแล้วปล่อยผ่าน**

### ตารางการตัดสินใจครบทุกกรณี

| สถานะปัจจุบัน | กดส่งใหม่ตอนไหน | ระบบทำอะไร |
|---|---|---|
| ยังไม่เคยส่ง | ก่อนกำหนด | ส่งได้ ไม่มีค่าปรับ |
| ยังไม่เคยส่ง | เลยกำหนด ≤ 3 วัน | ส่งได้ หักตามจำนวนวัน แสดงตัวเลขก่อนยืนยัน |
| ยังไม่เคยส่ง | เลยกำหนด > 3 วัน | ส่งได้เพื่อเก็บหลักฐาน คะแนน 0 **ไม่เรียก AI ตรวจ** |
| ส่งไว้แล้ว | ก่อนกำหนด | ส่งใหม่ได้ ไม่มีค่าปรับ |
| ส่งไว้แล้ว | เลยกำหนด ≤ 3 วัน | ส่งใหม่ได้ **ต้องยืนยันผ่านตารางเทียบก่อน/หลัง** |
| ส่งไว้แล้ว | เลยกำหนด > 3 วัน | **ปฏิเสธ** เพราะจะทำให้คะแนนที่มีอยู่เป็น 0 → ส่งต่อไปที่อาจารย์ |

### สิ่งที่หน้าจอต้องมีเพิ่ม (วาดใน prototype แล้ว)

1. **ตารางเทียบก่อน/หลังในป๊อปอัปยืนยัน** — เวลาส่ง · สถานะ · หักส่งช้า · คะแนนเต็มที่เป็นไปได้ เทียบสองคอลัมน์ เพราะเมื่อการส่งใหม่มีราคา มันคือธุรกรรม ไม่ใช่การบันทึกไฟล์
2. **หน้าแรกเลิกแสดง "แก้ไขได้ถึง (วันที่)"** เปลี่ยนเป็น **"ส่งใหม่ได้จนกว่าอาจารย์จะเริ่มตรวจ"** เพราะเส้นตายที่แท้จริงไม่ใช่วันที่อีกต่อไป และเป็นเหตุการณ์ที่นักศึกษาไม่รู้ล่วงหน้า
3. ข้อความปฏิเสธสองแบบเขียนไว้เต็ม (อาจารย์เริ่มตรวจแล้ว / จะทำให้คะแนนหายไป)

### กระทบตั๋วอื่น

- **ticket 17** — เหตุการณ์ "อาจารย์กดสั่งตรวจทั้งชุด" กลายเป็นสิ่งที่**ล็อกการส่ง** ไม่ใช่แค่สร้างงานเข้าคิว ต้องเพิ่มลงในผังลำดับและในโมเดลข้อมูล
- **ticket 19** — หน้าคิวงานรอตรวจต้องบอกอาจารย์ก่อนกดว่า **"กดแล้วนักศึกษาจะส่งใหม่ไม่ได้อีก"** และควรมีทางเปิดให้ส่งใหม่เป็นรายคน
- **ticket 12** — ทุกครั้งที่ส่งใหม่คือหลักฐานชุดใหม่ที่ต้องเก็บครบ ครั้งเก่าห้ามลบ
