**4. แผนการดำเนินงาน**

## วิธีทำ

1. เขียนเป็น Markdown ก่อนที่ `.scratch/ai-grading-agent/deliverables/`
2. แปลงเป็น Word ด้วย pandoc — ตรวจแล้วว่ามีบนเครื่อง


## ข้อกำหนดเรื่องวิธีเขียน (อาจารย์ระบุ 7 ส.ค. 69)

> "ช่วงที่เอา spec ไปให้นักศึกษาดู จะให้เขาออกความเห็นและแก้ไข"

**spec pack เป็นร่างสำหรับถกกับทีมโครงงาน ไม่ใช่ข้อกำหนดตายตัวที่ส่งไปให้ทำตาม** — เปลี่ยนวิธีเขียนพอสมควร:

- ทุกการตัดสินต้องเขียน **เหตุผลและทางเลือกที่ไม่เอา** ไว้ด้วย ไม่ใช่เขียนแต่ข้อสรุป — เพื่อให้นักศึกษาเถียงได้อย่างมีข้อมูล แทนที่จะเถียงจากความรู้สึกหรือยอมรับไปเฉย ๆ
- ต้องแยกให้ชัดว่าอะไรคือ **ข้อจำกัดที่ต่อรองไม่ได้** (โครงสร้างสองเครื่อง · กติกาส่งสาย · การสืบย้อนตาม TABEE · นักศึกษาไม่เห็นคะแนน AI) กับอะไรคือ **ข้อเสนอที่เปลี่ยนได้**
- ของที่ยังไม่ถูกทดสอบต้องติดป้ายว่ายังไม่ถูกทดสอบ โดยเฉพาะ wireframe ฝั่งนักศึกษาที่ยังไม่เคยผ่านสายตาผู้ใช้จริง

**ข้อสังเกตที่บันทึกไว้ตามตรง:** ทีมโครงงานรีวิว spec ในฐานะ**คนสร้าง** ไม่ใช่ในฐานะ**ผู้ใช้** — ความเสี่ยงที่ว่าไม่มีนักศึกษาผู้เรียนคนไหนเคยอ่านหน้าส่งงานเลย ยังไม่ถูกปิดด้วยการรีวิวรอบนี้ อาจารย์ตัดสินแล้วว่าข้ามไปก่อน (7 ส.ค. 69)

### วิธีเขียนที่ใช้จริง

ทำตามคำสั่งอาจารย์ 7 ส.ค. 69 ทุกข้อ — spec เขียนแบบ **ร่างสำหรับถก** ไม่ใช่ข้อกำหนดตายตัว: ทุกการตัดสินมีเหตุผลและทางเลือกที่ตัดทิ้งกำกับ · เล่ม 1 §1.5 มีตารางแยก **ข้อจำกัดที่ต่อรองไม่ได้ 8 ข้อ** ออกจาก **ข้อเสนอที่เปลี่ยนได้ 6 ข้อ** · ของที่ยังไม่ถูกทดสอบติดป้ายไว้ทุกจุด

### ช่องว่างที่เขียนไว้ตรง ๆ แทนที่จะเดาให้เต็ม

1. **ไม่มีข้อความต้นฉบับของโจทย์ข้อ 13 ในแฟ้ม** — เล่ม 1 §3.1 ระบุว่าต้องขอจากอาจารย์ก่อนถือว่า spec สมบูรณ์ และเขียนกำกับว่า *ห้ามเดาแล้วเขียนลงไป*
2. **ticket 18 (auth · บทบาท · PDPA) ยังไม่ถูกตอบเลย** — เล่ม 1 §4 เปิดหัวข้อด้วยป้าย ⚠ ว่ายังไม่สมบูรณ์ แทนที่จะแต่งข้อกำหนดความปลอดภัยขึ้นมาเอง
3. **เล่ม 4 §4.2** บันทึกไว้ตรง ๆ ว่าโครงงานพิสูจน์ "ลดเวลาอาจารย์ทั้งเทอม" ไม่ได้ในภาคทดลองของตัวเอง และต้องเปลี่ยนการเคลมเป็น "ที่ความแม่นเท่านี้ ใช้เวลาต่อชิ้นเท่านี้"

### บันทึกทางเทคนิคสำหรับคนที่ต้องสร้างเอกสารใหม่

- pandoc ตัวเปล่าใช้ธีมฟอนต์ Aptos และ **ไม่ตั้ง `w:cs` เลย** → ภาษาไทยจะ fallback แบบเดาไม่ได้ แก้ด้วย `reference.docx` ที่เก็บไว้ในโฟลเดอร์เดียวกัน ซึ่งตั้ง **TH Sarabun New** ทั้ง ascii/eastAsia/hAnsi/cs · ขยายขนาดฐาน 12→14 pt (TH Sarabun New ตัวเล็กกว่าฟอนต์ฝรั่งที่ขนาดเท่ากัน) · หน้า A4 ขอบ 1.8 ซม. ซ้ายขวาเพื่อให้ตารางกว้างลง
- คำสั่งที่ใช้: `pandoc -f markdown -t docx --toc --toc-depth=3 --reference-doc=reference.docx -o X.docx X.md`
- **เครื่องนี้ไม่มีฟอนต์ monospace ที่รองรับไทย** → บล็อกผังตัวอักษรที่มีข้อความไทยจะเหลื่อมเล็กน้อยใน .docx/.pdf แก้ไม่ได้ บรรเทาด้วยการตั้ง `w:cs="TH Sarabun New"` ให้สไตล์โค้ด
- ER diagram ในเล่ม 1 §2.3 เป็น **ซอร์ส Mermaid** ไม่ใช่รูป — วางลง <https://mermaid.live> เพื่อเรนเดอร์เป็นภาพก่อนใส่เล่มจริง
- **สารบัญของ .docx ต้องให้ Word refresh ก่อน** — pandoc `--toc` ออก field ที่ขึ้นว่า "no table of contents entries found" จนกว่าจะสั่ง update ทำผ่าน Word COM (`TablesOfContents.Update()` + `Save()`) ใช้เวลา 1–2 วินาทีต่อไฟล์ ทำไปแล้วทั้งสี่ไฟล์
- **อย่าวนลูป `AutoFitBehavior` ทุกตารางก่อน export** — ทำให้ Word ค้าง และไม่จำเป็นเพราะ pandoc ตั้ง `tblW = 100%` ให้อยู่แล้ว (ตารางที่เหลือเป็น `auto` ไม่กี่ตัว แก้ที่ XML ตรง ๆ เร็วกว่ามาก)

### PDF: เปลี่ยนเส้นทางจากที่ตั๋วสั่งไว้ — บันทึกไว้ให้ครบ

ตั๋วสั่งให้ได้ PDF ด้วยการเปิดใน Word แล้ว Save as PDF **ทำไม่สำเร็จ** — `Word.ExportAsFixedFormat` บนเครื่องนี้กินเวลาไม่จบ ไล่จนแน่ใจว่า**ไม่ใช่ปัญหาของเอกสาร**: เทสต์ด้วยเอกสารเปล่าที่มีข้อความบรรทัดเดียวก็ค้างเกิน 3 นาทีเหมือนกัน ขณะที่การเปิดไฟล์ · update สารบัญ · save · นับจำนวนหน้า ทำได้ในไม่กี่วินาที **พังเฉพาะฟังก์ชัน export PDF ของ Word เท่านั้น** (Word เผา CPU จริงตลอดเวลา ไม่ใช่ค้างรอ dialog)

เส้นทางที่ใช้แทน — **Chrome headless พิมพ์เป็น PDF จาก HTML ที่ pandoc สร้าง**:

```bash
pandoc -f markdown -t html5 --standalone --toc --toc-depth=3 \
  --css=doc.css --embed-resources --metadata lang=th -o X.html X.md
chrome.exe --headless --disable-gpu --no-pdf-header-footer \
  --print-to-pdf="X.pdf" "file:///.../X.html"
```

- เร็ว 1.6 วินาทีต่อไฟล์ · ฟอนต์ **TH Sarabun New ฝังในไฟล์ครบทั้งสี่หน้าตัด** (regular/bold/italic/bold-italic) + Tahoma กับ Segoe UI Symbol เป็นตัวสำรองสำหรับสัญลักษณ์ที่ Sarabun ไม่มี
- `doc.css` ที่ใช้เก็บไว้ที่ scratchpad — A4 ขอบ 18/16 มม. · ฐาน 15pt · `table-layout: fixed` + `word-wrap: break-word` ทำให้ **ไม่มีตารางไหนล้นหน้ากระดาษเลย** · `thead { display: table-header-group }` ให้หัวตารางซ้ำเมื่อตารางข้ามหน้า
- **กับดักที่เจอ:** `---` ใน Markdown ที่อยู่ติดหน้าหัวข้อ `#` กลายเป็น `<hr>` ที่ถูกดันไปอยู่หน้าเปล่าลำพัง เพราะ `h1` สั่งขึ้นหน้าใหม่ → ลบ `<hr>` ที่ติดหน้า `<h1>` ออกจาก HTML ก่อนพิมพ์ (รวม 30 จุดในสี่ไฟล์)
- **ข้อแลกเปลี่ยนที่ต้องรู้:** PDF จาก Chrome **ไม่มีเลขหน้า** และสารบัญเป็นลิงก์กดได้แทนที่จะบอกเลขหน้า (Chrome ไม่รองรับ CSS paged counters) · หน้าตาจึงไม่ตรงกับ .docx เป๊ะ ๆ — **.docx คือต้นฉบับที่เอาไปแก้ต่อ ส่วน .pdf ไว้ส่งอ่าน** ถ้าต้องการ PDF ที่มีเลขหน้าให้เปิด .docx ใน Word แล้ว Save as PDF ด้วยมือ (ทำมือได้ พังเฉพาะตอนสั่งผ่าน COM)
