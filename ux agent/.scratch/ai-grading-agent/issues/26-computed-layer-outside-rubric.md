# 26 — คะแนนสุดท้ายประกอบขึ้นจากอะไร: ชั้นที่ "คำนวณ" ต้องอยู่นอก rubric

Type: grilling (HITL)
Status: resolved (7 ส.ค. 69)
Blocked by: 25 ✅

> ตั๋วนี้เขียนใหม่ทั้งใบเมื่อ 2026-08-06 ฉบับแรกเสนอให้รื้อโมเดล rubric ให้รองรับสามรูปแบบที่พบใน[เอกสารตรวจงานของ TA](25-assignment-inventory.md) — **อาจารย์ตอบว่าให้ rubric ยืนตาม [ticket 10](10-rubric-structure-versioning.md) เหมือนเดิม** เพราะเอกสารนั้นคือระบบเก่าที่ตรวจด้วยมือ ระบบใหม่ปรับรูปแบบได้อยู่แล้ว
>
> สิ่งที่เหลืออยู่หลังตัดข้อเสนอนั้นออก คือคำถามที่ไม่ได้มาจากเอกสาร แต่มาจาก**โครงสร้างของคะแนนเอง** — และยังไม่มีตั๋วไหนตอบ

## Question

**คะแนนที่นักศึกษาเห็นในช่องสุดท้าย ประกอบขึ้นจากอะไรบ้าง และ rubric รับผิดชอบส่วนไหนของมัน?**

ทุกวันนี้แผนที่พูดเหมือนว่า `คะแนน = ผลของ rubric` แต่ของจริงมีอย่างน้อยสามชั้นซ้อนกัน และสองชั้นในนั้น **ไม่ควรผ่าน AI เลย**

| ชั้น | ตัวอย่าง | ใครตัดสิน | ผ่าน LLM ไหม |
|---|---|---|---|
| 1. คะแนนตาม rubric | เกณฑ์แต่ละข้อ × ระดับ | AI เสนอ / อาจารย์ยืนยัน | ✅ |
| 2. นโยบายรายวิชา | หักส่งสาย · ไม่ส่ง = 0 · สายเกินกำหนด = 0 | ระบบ (กติกาแน่นอน) | ❌ |
| 3. ดุลพินิจล้วน | "ทำได้ดีเกินคาด บวกให้" | อาจารย์เท่านั้น | ❌ |

ถ้าไม่แยกสามชั้นนี้ให้ชัดตั้งแต่ตอนออกแบบ ทุกอย่างจะถูกยัดเข้า rubric แล้วเราจะได้ระบบที่ **AI เดาว่านักศึกษาส่งสายกี่วัน** ซึ่งเป็นเรื่องที่ฐานข้อมูลรู้แน่นอนอยู่แล้ว

### ประเด็นที่ต้องตัดสิน

**1. ชั้นนโยบายเป็นของรายวิชา หรือของงานแต่ละชิ้น?**
กติกาส่งสายที่พบในระบบเดิม (หัก 10% ของคะแนนเต็มต่อวัน · หักจนติดลบให้ 1 คะแนน · ไม่ส่ง = 0 · สายเกิน 3 วัน = 0) เขียนไว้ครั้งเดียวใช้ทั้งวิชา
→ ถ้าตั้งที่ระดับรายวิชา อาจารย์ตั้งครั้งเดียวจบ แต่ถ้าบางงานอยากผ่อนผัน (เอกสารเดิมผ่อนผันให้นักศึกษาฝึกงาน) ต้อง override ได้ที่ชิ้นงาน
→ เกี่ยวโยงกับ [ticket 09](09-...) โดยตรง: ค่าที่คำนวณได้แบบนี้ต้อง trace ได้ว่ามาจากกฎข้อไหน ไม่ใช่แค่ตัวเลขที่โผล่มา

**2. งานที่ "แค่เช็คว่าส่ง" ต้องมี rubric ไหม?**
requirement ข้อ 7 เขียนว่า *"1 ชิ้นงานมี 1 rubric ขึ้นไป"* — แต่งานบางชิ้นให้คะแนนแค่ส่ง/ไม่ส่ง การบังคับสร้าง rubric กับงานพวกนี้คือพิธีกรรมเปล่า ๆ และแย่กว่านั้นคือ**อาจทำให้ระบบเรียก AI ไปตรวจงานที่ไม่มีอะไรให้ตรวจ**
→ ทางเลือก: (i) ยอมให้ชิ้นงานมี 0 rubric ได้ (แก้ requirement) (ii) มี rubric ชนิด "เช็คส่ง" สำเร็จรูปที่ระบบให้มา ไม่ต้องเขียนเอง

**3. เกณฑ์ที่ล็อกว่า human-only ควรมีที่ยืนในโมเดลไหม?**
เกณฑ์แบบ "ถ้าดูแล้วประทับใจบวกเพิ่ม" ไม่มี anchor และวัด agreement ไม่ได้เลย
→ ข้อเสนอ: ให้ criterion มีธง `human_only` — AI แสดงช่องว่างพร้อมข้อความ *"ข้อนี้ระบบไม่ให้คะแนน"* แทนที่จะเดา
→ คุณค่าในเล่ม: เป็นหลักฐานว่าเรารู้ขอบเขตของตัวเอง มากกว่าจะเป็นข้อจำกัดที่ต้องขอโทษ
→ ผลต่อการวัด: เกณฑ์ที่ติดธงนี้ต้อง**ถูกตัดออกจากการคำนวณ agreement** ไม่งั้นตัวเลขจะเพี้ยน

**4. เมื่อไหร่ที่ระบบต้อง "ไม่เรียก AI เลย"?**
สายเกินกำหนด = 0 · ไม่ส่ง = 0 · งานเช็คส่ง — สามกรณีนี้ตัดสินได้ก่อนถึง AI
→ ไม่ใช่แค่เรื่องประหยัดค่า token แต่เป็นเรื่องความหมาย: ถ้าระบบยังตรวจงานที่ได้ 0 แน่นอนแล้ว feedback ที่ออกมาจะสับสนสำหรับนักศึกษา
→ ต้องมีจุดตัดสินใจนี้อยู่ก่อน pipeline ตรวจ ไม่ใช่กรองทีหลัง

### สิ่งที่ตั๋วนี้ **ไม่** ตั้งคำถาม

โครงสร้าง rubric เอง — ตาราง criterion × ระดับ พร้อมคำบรรยายแต่ละระดับ, `RubricVersion` และการแช่แข็งเวอร์ชัน — **ยืนตาม ticket 10 ทั้งหมด** จำนวนระดับต่อ rubric เป็นเรื่องที่ตั้งได้ต่อ rubric อยู่แล้ว ไม่ใช่คำถามเชิงโครงสร้าง

## อาจารย์ตอบคำถามหลักแล้ว (6 ส.ค. 69 — ระหว่างทดลอง prototype ของ ticket 19)

> **"ตั้งที่รายวิชา override ได้ที่ชิ้นงาน"**

**นโยบายส่งช้าอยู่สองระดับ:** ค่าตั้งต้นอยู่ที่รายวิชา (หน้าจอ 02 ของ prototype ฝั่งอาจารย์) และ override ได้เป็นรายกิจกรรม (หน้าจอ 07) ทุกครั้งที่ override ต้องบันทึกว่าใครเปลี่ยน เปลี่ยนเมื่อไหร่ เปลี่ยนจากอะไร — เพราะการผ่อนผันเป็นรายกรณีคือจุดที่ต้องอธิบายได้ภายหลัง

**คำตอบข้อ 5 ของรอบเดียวกันขยายขอบเขตตั๋วนี้:** อาจารย์เลือกให้ระบบเก็บคะแนนของกิจกรรมที่ไม่ได้ตรวจด้วย (สอบกลางภาค ปลายภาค นำเสนอ) แปลว่า **ชั้นที่คำนวณนอก rubric ไม่ได้มีแค่การหักส่งช้า** แต่มีการรวมคะแนนตามสัดส่วนของรายวิชาและการเสนอเกรดด้วย ทั้งสามอย่างเป็นเลขคณิตล้วน ไม่ผ่าน LLM

**สิ่งที่ยังต้องตัดสินในตั๋วนี้:** ชั้นดุลพินิจล้วน (`human_only`) ยังไม่ได้ออกแบบหน้าตา · ระบบเสนอเกรดแล้วอาจารย์ยืนยัน หรือระบบตัดให้เลย (เสนอ: เสนอเท่านั้น) · ลำดับการคำนวณเมื่อทั้งสามชั้นชนกัน

## ปิดตั๋ว — ตัดสินสามข้อที่ค้าง (7 ส.ค. 69)

สามข้อนี้เป็นการออกแบบที่อนุมานได้จากการตัดสินที่มีอยู่แล้ว ไม่ใช่คำถามที่ต้องให้อาจารย์เลือก จึงตัดสินพร้อมเหตุผลไว้ที่นี่ **และเป็นข้อเสนอที่ทีมนักศึกษาแย้งได้** ตามสถานะของ spec pack ใน [ticket 24](24-assemble-spec-pack.md)

### A. หน้าตาของชั้นดุลพินิจ — ไม่มีช่องพิมพ์ "คะแนนสุดท้าย" ที่ไหนเลยในระบบ

ดุลพินิจของอาจารย์ปรากฏได้ **สองที่เท่านั้น** และทั้งสองที่เป็นการวางทับ ไม่ใช่การเขียนทับ

| ที่ | รูปแบบ | บังคับเหตุผล |
|---|---|---|
| ในเกณฑ์ | เปลี่ยนระดับที่ AI เสนอ | ✅ (ตาม [ticket 12](12-score-traceability.md)) |
| นอกเกณฑ์ | **รายการปรับ** — เครื่องหมาย +/− · จำนวนคะแนน · เหตุผล | ✅ |

เกณฑ์ที่ติดธง `human_only` แสดงเป็นช่องว่างพร้อมข้อความ *"ข้อนี้ระบบไม่ให้คะแนน"* — **ยังนับเข้าคะแนนเต็มตามปกติ** (ไม่งั้นคะแนนเต็มของแต่ละคนไม่เท่ากัน) แต่ **ตัดออกจากการคำนวณ agreement** ทุกตัว

**เหตุผลที่ห้ามมีช่องพิมพ์คะแนนสุดท้าย:** ถ้ามี ทุกชั้นที่ออกแบบมาจะถูกข้ามด้วยการพิมพ์ตัวเลขทับ แล้วโจทย์ข้อ 9 (สืบย้อนที่มาของคะแนน) จะตอบไม่ได้ในกรณีที่สำคัญที่สุด คือกรณีที่อาจารย์ไม่เห็นด้วยกับระบบ

### B. เกรด — ระบบเสนอ อาจารย์ยืนยัน ระบบตัดเองไม่ได้

ระบบคำนวณคะแนนรวมตามสัดส่วนของรายวิชา แสดงการกระจายของทั้งชั้น และ**เสนอ**จุดตัดเกรด อาจารย์ปรับจุดตัดได้และต้องกดยืนยันเสมอ

- จุดตัดเกรดเป็นดุลพินิจที่ขึ้นกับการกระจายของทั้งชั้น ไม่ใช่ฟังก์ชันของคะแนนรายคน
- [TABEE ข้อ 1.7](05-clo-outcome-based-assessment.md) ต้องสืบย้อนได้ว่า**ใคร**ตัดสิน — "ระบบตัดให้" ไม่มีคนตอบ
- `GradeSnapshot` ของ [ticket 12](12-score-traceability.md) แช่แข็ง **ตอนกดยืนยัน** ไม่ใช่ตอนคำนวณ

### C. ลำดับการคำนวณ — สิ่งที่ต้องล็อกจริงคือตำแหน่งของ "พื้น" ไม่ใช่ลำดับของการบวกลบ

ทั้งสามชั้นเป็นการบวกลบจำนวนคะแนน จึงสลับลำดับกันแล้วได้ผลเท่ากัน **ยกเว้นกฎพื้น** ซึ่งไม่ใช่การบวกลบ ลำดับที่ล็อกจึงมีสองเหตุผล: ให้กฎพื้นทำงานถูก และให้หน้าจออธิบายที่มาของตัวเลขกับนักศึกษาได้เป็นบรรทัด ๆ

```
ขั้น 0  ประตูก่อนถึง AI   ไม่ส่ง = 0 · ส่งช้าเกิน 3 วัน = 0   → จบ ไม่เรียก AI เลย
ขั้น 1  คะแนนตาม rubric   (คะแนนกลุ่ม)
ขั้น 2  + การปรับรายบุคคล  (ticket 11 · บังคับเหตุผล)
ขั้น 3  − ค่าปรับส่งช้า    10% ของคะแนนเต็มต่อวัน นับจาก **เวลาของครั้งที่ถูกใช้ตรวจ** (ticket 20)
ขั้น 4  พื้น              ถ้าผลรวม ≤ 0 → 1 คะแนน
```

**พื้นอยู่ล่างสุดเสมอ** — ถ้าเอาการปรับรายบุคคลไว้หลังพื้น คนที่ส่งช้าจนติดพื้นแล้วได้บวกดุลพินิจ จะจบสูงกว่าคนที่ส่งตรงเวลาและทำงานเท่ากัน

**หน้าจอต้องแสดงทั้งสี่บรรทัด ไม่ใช่แสดงแต่ผลลัพธ์** ทั้งฝั่งอาจารย์และฝั่งนักศึกษา (ตรงกับที่ [ticket 20](20-wireframes-student.md) วาดไว้แล้วในหน้าผลการตรวจ)
