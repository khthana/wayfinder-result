# ผังหน้าจอระบบ — ฉบับรวมร่างของอาจารย์กับสิ่งที่ตกหล่น

เอกสารนี้เอาร่างหน้าจอในไฟล์ `UX AI Agent.docx` มาตั้งเป็นแกน แล้วเติมสิ่งที่ตกหล่นเมื่อเทียบกับสิ่งที่ตัดสินกันไว้แล้วใน `.scratch/ai-grading-agent/CONTEXT.md`, เอกสารฉบับที่ 1 (System Specification) และเอกสารฉบับที่ 2 (UI Design) — **จัดเรียงใหม่ตามฟังก์ชัน ไม่ใช่ตามลำดับในร่างเดิม**

## สัญลักษณ์

| สัญลักษณ์ | ความหมาย |
|---|---|
| 🟦 **เดิม** | ข้อความจากร่างของอาจารย์ **คัดมาตามตัวอักษร** เลขในวงเล็บคือข้อในร่างเดิม |
| 🟩 **เพิ่ม** | สิ่งที่ผมเติมเข้ามา เพราะเป็นผลบังคับจากการตัดสินใจที่ยืนยันไปแล้ว หรือจากข้อกำหนด PDPA |
| 🟨 **ต้องยืนยัน** | ข้อความเดิมที่ชนกับสิ่งที่ตัดสินไปแล้ว ต้องเลือกอย่างใดอย่างหนึ่งก่อนลงมือ |

สถานะ MVP อ้างตามผังหน้าจอ §8 ของเอกสารฉบับที่ 1 — `MVP` ทำในรอบแรก · `ทีหลัง` ออกแบบไว้แล้วแต่ไม่ทำในรอบแรก

# ภาคผนวก ก — สิ่งที่จงใจไม่ทำ

ไม่ใช่ของตกหล่น แต่บันทึกไว้กันเข้าใจผิดว่าลืม

| สิ่งที่ไม่มี | เหตุผล |
|---|---|
| ปุ่มทักท้วงคะแนนในระบบ | ตัดสินแล้ว — ใช้ช่องทางพบอาจารย์จริงแทน และต้องเขียนวันเวลาสถานที่ไว้บนหน้าผลการตรวจ |
| การแจ้งเตือนทางอีเมล / push | ยังไม่มีหลักฐานว่าจำเป็น นักศึกษาเข้าระบบตามเดดไลน์อยู่แล้ว |
| ช่องกรอกคะแนนสุดท้าย | ตัดสินแล้ว ทุกจอ |
| ระบบสิทธิ์ที่ตั้งค่าได้เอง | บทบาทสี่แบบตายตัว |
